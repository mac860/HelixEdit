# HelixEdit 0.1.6 beta — accurate sequence-to-plasmid-map behavior

## Reference and verified facts

Primary reference: [Addgene #10878 — pLKO.1–TRC cloning vector, sequences](https://www.addgene.org/10878/sequences/) and [Addgene Sequence Analyzer, entry 438456](https://www.addgene.org/browse/sequence/438456/).

Addgene lists one full Addgene-verified sequence and three partial verified sequences for this vector. Its analyzer presents restriction sites, feature coordinates, primers and a strand display. These are not all inferable from a bare FASTA string. Addgene also provides annotated maps when the corresponding annotation data is available to the user. This project references these public descriptions, but does not distribute Addgene's application assets, protected data, or attempt to bypass account requirements.

The user supplied a raw \`>Addgene_NGS_Result\` sequence and a screenshot of an annotated 8,901 bp plasmid map. We have **not independently compared the entire pasted sequence character-for-character with Addgene's restricted full-sequence file**. Therefore the app must show the pasted sequence's actual length and must never force 8,901 bp or claim exact identity based only on its name.

## Why the old map did not match

1. \`parseFasta()\` created **linear** topology for all FASTA records.
2. Only eight short exact restriction motifs were surveyed.
3. The circular map drew features only from manually supplied \`Record.features\`, and small views hid most feature labels.
4. There was no direct workflow for importing GenBank annotations **onto a matching existing FASTA record**, only opening or appending GenBank records.

A precise map must distinguish **computed data** (length, recognition motifs, geometry) from **external annotations** (origins, promoters, antibiotic resistance, primer names).

## Changes on main

- Map → **Circular DNA** explicitly sets topology for the active DNA/RNA record, synchronized with undo and the saved project. Topology is never inferred from a generic FASTA header.
- **26 exact palindromic recognition motifs**, checked with efficient \`QStringView\` comparisons, including sites spanning the circular origin. All hits use zero-based internal recognition starts and 1-based displayed start coordinates. This is *not* a cleavage-position, methylation or reaction-condition model. The catalog and notation can be checked against [NEB's recognition-specificity list](https://www.neb.com/en/tools-and-resources/selection-charts/alphabetized-list-of-recognition-specificities).
- Dynamic site count and feature count in the Map heading. Recognition sites are recalculated when a sequence is edited, and circular versus linear origin-spanning recognition is handled separately.
- Strand-aware arrows for existing feature ranges. Map labels use source feature names and coordinates and are distributed with a collision-avoidance rule. Excess labels can be inspected in the Features and Enzymes tabs.
- The **Unique sites** checkbox shows only single-occurrence recognition motifs for a less crowded map. The full Enzymes tab remains available.
- File → **Attach matching GenBank annotations to active sequence…** and Features → **Import matching GenBank annotations…** verify the sequence **exactly matches** (ungapped, same orientation, same circular origin). Only then are simple interval features and donor topology transferred. The current project is not modified when the sequences disagree.
- FASTA import now warns that topology and annotations are not encoded. Single-base edits on annotated sequences produce a revalidation warning.

## Steps with Addgene #10878

1. Save the user's complete \`Addgene_NGS_Result\` sequence as a local FASTA file and import it into HelixEdit.
2. Check **Map**: the central and heading lengths must equal the actual imported base count. Independently compare the record against Addgene's authenticated reference. Do not infer a match solely from a plasmid name.
3. Confirm circularity from the relevant source and enable **Circular DNA**. Only then are origin-spanning motif sites included.
4. Inspect **Enzymes** for exact motif recognition starts; disable **Unique sites** to display more labels if the window is large enough.
5. For gene/promoter/ori and other named features, obtain the matching annotated GenBank from Addgene (when accessible). Use File → **Attach matching GenBank annotations to active sequence…**. If the active FASTA and GenBank sequences differ in bases, start, orientation or variants, import fails rather than misplacing labels. An alternative is opening the annotated GenBank as a new record.
6. Compare highlighted features and coordinate ranges to the original Addgene record; check that unsupported complex \`join()\` GenBank locations are not silently shown as contiguous features. Exact interpretation of pLKO.1 requires verified original annotations.

## Limitations

- The 26-motif recognition library covers a carefully chosen subset of enzymes, not REBASE or Addgene's full restriction catalog. Motif sites ≠ cleavage sites ≠ digestion predictions.
- Matching GenBank sequences with a rotated circular origin or reverse complement are *not automatically remapped*. We deliberately reject them until validated coordinate rotation/transformation is implemented.
- \`Feature\` supports a single contiguous half-open interval. Complex joined/complement structures and advanced GenBank metadata remain out of scope.
- The map does not identify AmpR, puromycin resistance, bacterial origins, promoters or other named genes from raw DNA. Correct automatic functional annotation would require validated reference databases and sequence-alignment evidence.
- Annotation graphics prioritize legibility on limited displays; some labels may be hidden but are still listed in the Features tab.
- This is a **beta implementation**; completed Ubuntu 26.04 / macOS native compilation and independent base-by-base comparison against the original Addgene sequence have not been obtained here.

## Tests

- \`tests/restriction_tests.cpp\`: exact recognition coordinates for EcoRI, NheI, KpnI, MluI, origin-spanning EcoRI, and mutation-driven site disappearance.
- \`tests/core_tests.cpp\`: FASTA contains no implied topology/feature labels; sequence-matched GenBank annotation transfer works, mismatches and rotations are rejected.
- \`tests/editor_tests.cpp\`: circular topology toggling and dynamic map rendering after a substitution removing EcoRI.
