# HelixEdit 0.1.3 beta — Preferences, updater, bundled examples

This is the current development branch. The 0.1.3 source has not yet been confirmed through completed multi-platform compilation and automated CI.

## Centralized Settings

Use **Settings → Preferences…**, toolbar **Settings**, or **Ctrl+,**. The Appearance menu and duplicate tool-configuration entries were replaced with one dialog.

| Tab | Editable preferences | Local key |
| --- | --- | --- |
| Appearance | Light / Dark / Dracula | `appearance/theme` |
| Appearance | Startup Map or Sequence view | `workspace/startTab` |
| Map & editing | Show enzyme recognition-site callouts | `map/showEnzymes` |
| Map & editing | Show annotated features | `map/showFeatures` |
| Map & editing | Default circular-map zoom (65–135%) | `map/defaultZoom` |
| Map & editing | Autosave interval 30/60/120/300 seconds | `editing/autosaveSeconds` |
| Scientific tools | MAFFT, MUSCLE, blastn, blastp, primer3_core | `tools/<toolname>` |
| Updates | Existing, clean local Git checkout | `updater/source` |

All are stored using **QSettings** in the current user profile. Saving changes reapplies the theme and updates the live map and autosave timer; settings are not embedded in biological sequence files. The **Restore defaults** button populates the default fields, but **Save settings** is still required to commit them.

## Update without downloading the repository again

The app's **Update** button or Settings → Update from GitHub source opens the user-controlled update assistant. The assistant invokes `scripts/update_from_source.sh`. It checks that the checkout is `mac860/HelixEdit` on branch `main`, refuses dirty tracked files and divergent history, and fast-forwards the source without resetting local work. It then compiles, runs CTest, creates a Debian package, and requests Polkit authorization through `pkexec` only for the install step.

There is **no automatic scheduling**, no background periodic update check, and no upload of DNA, RNA or protein data. If the source is already current, explicit **Update & install** still rebuilds and reinstalls that source. This supports replacing an older installed version with code already downloaded to disk.

Before using the in-app assistant, install this beta version once using `git pull --ff-only origin main && bash scripts/build_ubuntu_deb.sh` followed by `sudo apt install ./build-ubuntu-amd64/HelixEdit-0.1.3-x86_64.deb`. A local Git clone is required; a ZIP extraction lacks Git metadata.

## Teaching examples

File → Open teaching examples, or the toolbar Examples menu, loads 6 DNA, 3 simulated RNA and 5 protein FASTA records from embedded Qt resources. They are also installed at `/usr/share/helixedit/examples/samples/` on Linux. See [source/provenance details](../examples/samples/README.md).

## Validation checklist

1. Build source and `.deb` with `scripts/build_ubuntu_deb.sh` on Ubuntu x86_64; run CTest with the Qt offscreen platform plugin.
2. Open Preferences; switch Light / Dark / Dracula; verify map colors and persisted selection after restart.
3. Change map layers, zoom and autosave; confirm controls and timer reflect the saved state.
4. Set and clear optional executable paths; check MAFFT/MUSCLE/BLAST+/Primer3 integration with known samples.
5. Load bundled DNA, RNA and protein collections offline and verify the number of records, alphabet and maximum record length.
6. Open About and verify the developer credit and working repository/email links.
7. Test Check GitHub, no-op update when current, clean-source fast-forward, build/test failure, and cancelled Polkit install without altering user projects.
8. Check Linux ARM64 and macOS builds separately. The in-app DEB installer is Linux-only.

Do not publish a stable release before the target-platform tests complete.
